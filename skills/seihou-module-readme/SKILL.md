# Seihou Module README

Reference documentation for registry artifacts is **generated**, not hand-written. The
seihou OKF extension (`seihou-okf-extension docs`) reads a registry's
`seihou-registry.dhall` and every artifact's `.dhall` file, and writes an OKF bundle
(`okf-docs/` at the registry root) with one page per module, recipe, blueprint, and
prompt. Each page already covers everything the artifact declares: dependencies and
their bindings, variables (type, requiredness, default, validation, description),
exports, prompts, generation steps, commands, removal, migrations, and for blueprints and
prompts the agent prompt, reference files, tool allowlist, and launch preferences.

So this skill does not synthesize documentation. It:

1. Locates the artifact and the registry it is published in.
2. Regenerates the registry's `okf-docs/` bundle so the page is current.
3. Writes a short `README.md` next to the artifact's `.dhall` file that points to the
   generated page.

The README must never restate variables, steps, or other declared fields — that copy
would drift from the `.dhall` source, which is exactly the problem the generated bundle
solves.

## When to Use

Activate when the user says things like:

- "Add a README to this module"
- "Document this seihou module / recipe / blueprint"
- "Refresh the module README"
- "Point the README at the generated docs"
- "/seihou-module-readme"

## Key Concepts

### Registry root and bundle layout

The registry root is the nearest ancestor directory containing `seihou-registry.dhall`.
The bundle lives at `<REGISTRY_ROOT>/okf-docs/`:

```text
okf-docs/
  index.md
  profile.dhall
  modules/<name>.md
  recipes/<name>.md
  blueprints/<name>.md
  prompts/<name>.md
  registry/<repo>.md
```

`<name>` is the entry's `name` in `seihou-registry.dhall`, not necessarily the directory
name. Find it by matching the entry whose `path` equals the artifact directory relative to
the registry root.

### Artifact kinds

| Kind      | Definition file   | Registry field | Bundle page                    |
|-----------|-------------------|----------------|--------------------------------|
| module    | `module.dhall`    | `modules`      | `okf-docs/modules/<name>.md`    |
| recipe    | `recipe.dhall`    | `recipes`      | `okf-docs/recipes/<name>.md`    |
| blueprint | `blueprint.dhall` | `blueprints`   | `okf-docs/blueprints/<name>.md` |
| prompt    | `prompt.dhall`    | `prompts`      | `okf-docs/prompts/<name>.md`    |

### The bundle is derived

Never hand-edit `okf-docs/`. To change what a page says, change the `.dhall` source and
regenerate. Regenerating an unchanged registry is byte-identical, so the bundle diffs
cleanly in review.

## Instructions for Claude

### Phase 1: Locate the Artifact and Registry

If the user named an artifact or path, use it; do not re-ask. Otherwise:

```
Question: "Which artifact should I document?"
Header: "Artifact"
Options:
- Current directory
- Let me provide a path
- Pick from the registry's seihou-registry.dhall
```

Resolve:

- `ARTIFACT_DIR` — absolute path containing exactly one of `module.dhall`,
  `recipe.dhall`, `blueprint.dhall`, `prompt.dhall` (this sets `KIND`).
- `REGISTRY_ROOT` — nearest ancestor of `ARTIFACT_DIR` containing
  `seihou-registry.dhall`.
- `NAME` — the registry entry whose `path` matches `ARTIFACT_DIR` relative to
  `REGISTRY_ROOT`.

Fail fast with a clear message if:

- No definition file exists in `ARTIFACT_DIR`.
- No `seihou-registry.dhall` is found above it. The OKF extension only documents
  registry-published artifacts; tell the user to add the artifact to a registry first.
- The artifact is not listed in `seihou-registry.dhall`. Tell the user to register it
  (the page will not exist otherwise).

Installed copies under `.seihou/` are not a documentation target — use the source
registry.

### Phase 2: Validate and Sync

From `REGISTRY_ROOT`:

```bash
seihou validate-module <ARTIFACT_DIR>   # modules only
seihou registry sync-versions           # so the page records the current version
seihou registry validate
```

If any of these fail, surface the error and stop. `sync-versions` may modify
`seihou-registry.dhall`; mention that in the summary.

### Phase 3: Regenerate the OKF Bundle

From `REGISTRY_ROOT`, prefer the extension host:

```bash
seihou extension run okf -- docs --dir . --out okf-docs --force
```

If the extension host cannot find it but `seihou-okf-extension` is on `PATH`, run it
directly:

```bash
seihou-okf-extension docs --dir . --out okf-docs --force
```

If neither is available, stop and tell the user the extension must be installed
(it ships in `mori://shinzui/seihou` as the `seihou-okf-extension` package). Do not fall
back to writing reference documentation by hand.

The generator validates the bundle before writing and refuses to write on failure; if it
fails, surface the error and stop. If the `okf` CLI is available, optionally confirm:

```bash
okf validate okf-docs --strict --profile okf-docs/profile.dhall --profile-enforce
```

Then confirm `PAGE = <REGISTRY_ROOT>/okf-docs/<kind>s/<NAME>.md` exists. Read only its
frontmatter (enough to confirm `title` and `resource`); do not copy its body into the
README.

### Phase 4: Handle an Existing README

If `ARTIFACT_DIR/README.md` exists, read it. Older READMEs typically duplicate the
generated reference (Variables tables, Generated Files, Dependencies, Usage, and so on).
That content is obsolete and is dropped.

If the existing README also contains prose the generated page cannot provide — design
rationale, caveats, worked examples, migration advice — ask:

```
Question: "The existing README has hand-written notes not covered by the generated docs. Keep them?"
Header: "Notes"
Options:
- Keep them under a Notes section (Recommended)
- Drop them, README only points to the generated docs
- Show me the proposed README first
```

Only carry over prose that is not a restatement of declared fields. Content already in
`<!-- keep:begin -->` / `<!-- keep:end -->` markers is always kept.

### Phase 5: Write README.md

Compute `PAGE_LINK`, the path from `ARTIFACT_DIR` to `PAGE` (e.g.
`../../../okf-docs/modules/haskell-library.md`), and `ARTIFACT_REL`, the artifact
directory relative to `REGISTRY_ROOT`.

Write `ARTIFACT_DIR/README.md` using this template:

````markdown
# <NAME>

Reference documentation for this <KIND> is generated from `<definition file>` by the
seihou OKF extension:

**[<NAME> reference](<PAGE_LINK>)**

It covers everything the <KIND> declares — <kind-specific list, see below>.

Do not document those details here. Change `<definition file>` and regenerate from the
registry root:

```bash
seihou registry sync-versions
seihou extension run okf -- docs --dir . --out okf-docs --force
```

<!-- keep:begin name="notes" -->
## Notes

<carried-over hand-written prose>
<!-- keep:end -->
````

Kind-specific list for the "It covers" sentence:

- module: dependencies, variables, exports, prompts, generation steps, commands, removal,
  and migrations
- recipe: composed modules and their variable bindings, variables, and prompts
- blueprint: base modules, the agent prompt, variables, prompts, reference files, tool
  allowlist, launch preferences, version probe, and migration edges
- prompt: the agent prompt, variables, prompts, command-derived variables, guidance
  blocks, reference files, tool allowlist, and launch preferences

Rules:

- Omit the Notes block entirely when there is nothing to keep.
- Do not copy the version, variables, steps, or any other declared field into the
  README. The only duplicated fact is the name.
- Use a relative link so it works on GitHub and in local checkouts.

### Phase 6: Summarize

Report:

```
## README Updated: <NAME> (<KIND>)

### Files
- `<ARTIFACT_DIR>/README.md` (<created | replaced>)
- `<REGISTRY_ROOT>/okf-docs/` (regenerated; <changed | unchanged>)
- `<REGISTRY_ROOT>/seihou-registry.dhall` (<version synced | unchanged>)

### Generated Page
- `okf-docs/<kind>s/<NAME>.md`

### Next Steps
1. Review the generated page; fix anything wrong in `<definition file>`, not the page.
2. Commit:
   ```bash
   git add <ARTIFACT_REL>/README.md okf-docs seihou-registry.dhall
   git commit -m "docs(<NAME>): point README at generated OKF docs"
   ```
```

Use `git status --short okf-docs seihou-registry.dhall` to fill in changed/unchanged.

## Important Notes

- **Generated docs are the source of reference truth.** The README is a signpost.
- **Never hand-edit `okf-docs/`.** Fix the `.dhall` and regenerate.
- **Never edit the artifact's `.dhall` from this skill.** If a description or variable
  doc is missing or wrong on the generated page, tell the user which field to edit.
- **Always regenerate before linking**, so the README never points at a missing or stale
  page.
- **The README lives next to the definition file**, never inside `files/`, where it
  would be templated into generated projects.
